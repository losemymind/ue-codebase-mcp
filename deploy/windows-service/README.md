# Windows Agent service baseline

`manage-agent-service.ps1` manages only the fixed `UECodebaseMcpAgent` service. It defaults to non-mutating `Plan`, confines release and evidence paths below an explicit install root, rejects release reparse points, verifies approved executable/configuration SHA-256 values, and requires a valid Authenticode signature from the approved signer. It accepts only the service virtual account or a strictly named gMSA and never accepts, stores or forwards a password. Recovery remains two delayed restarts followed by a stopped state.

Install starts the service and requires exact `ready` content from the configured HTTPS `/health/ready` endpoint within a fixed deadline. Update requires the complete path, hashes and signer thumbprint for a distinct approved previous release before the new release can be selected. If new-release readiness fails, the workflow restores that already-verified previous release and verifies readiness again. `Rollback` is also an explicit operator action and can select only those approved previous-release inputs; arbitrary SCM history is never trusted as rollback authority.

Each mutating attempt writes content-safe JSON evidence below the install root. The evidence directory rejects reparse points and has inheritance removed with access restricted to LocalSystem and the local Administrators group. Evidence records action, bounded outcome, service identity, readiness origin and approved executable hashes, never configuration content, credentials, tokens or error text. Protect and export this directory according to the operations retention policy before changing or removing an installation.

Production installation still requires the signed `ue-codebase-mcp-agent.exe`, a validated configuration containing only `secret_ref`, the approved service identity, install root, trusted TLS readiness endpoint and host ACLs. This repository does not claim that a service was installed, updated or rolled back on the development machine.
